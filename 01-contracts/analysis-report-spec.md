# 表单 JS 分析报告 - 阅读指南

本文档说明「表单 JS 分析」工具的两份输出：**Markdown 报告** 和 **字段映射模板**。

## 工具用途

从蓝凌 EKP 低代码表单 HTML 中提取 JSP 片段的 JS 代码，识别 JS 中引用的表单控件，标注每个控件的「入参/出参」角色，并生成字段映射模板供迁移使用。

主要用途：

1. **人工审阅**：快速了解一段 JSP 表单 JS 涉及了哪些控件、做了什么操作
2. **迁移 Agent 输入**：作为 JSP → React 迁移的上下文，让 Agent 知道需要处理哪些字段、哪些是数据源、哪些是数据目标
3. **字段映射**：通过模板将旧系统字段 ID 与新系统字段 ID 建立对应关系

## 输出一：Markdown 报告

### 报告结构

报告按固定顺序包含以下章节：

1. **表单元信息** — 表单的主表/子表结构、业务控件总数、JSP 片段数量
2. **JS 片段（合并）** — 所有 JSP 片段中的 JS 代码（已清洗）
3. **JS 引用的控件** — JS 中实际引用的控件清单（**核心章节**）
4. **未匹配引用** — JS 中调用了已知 API 但参数不在控件字典中的情况
5. **全局钩子** — 是否声明了 `XFormOnValueChange` 或向其 push 函数
6. **按 label 引用** — 通过 ByLabel API 引用控件的罕见情况
7. **解析警告** — 解析过程中的异常（无异常时整节省略）

空章节统一显示 `（本次无）`，保持结构一致。

## 核心章节：JS 引用的控件

### 表格列定义

| 列名 | 含义 |
|---|---|
| **控件 ID** | 控件的唯一标识（`fd_xxx` 格式或用户自定义 ID） |
| **label** | 控件的显示标签；为空时显示 `(无 label)` |
| **类型** | 控件的 `fd_type`（如 `inputText`、`select`、`relationSelect` 等） |
| **所属表** | `主表` 或 `子表: <子表 label>`；无归属时显示 `(未归属)` |
| **直接引用** | 控件 ID 作为独立 token 在 JS 全文中出现的次数（不含被行级引用消费的部分）；0 时显示 `—` |
| **行级引用** | 以 `<子表ID>.<行号>.<字段ID>` 格式出现的次数（仅子表字段有）；0 时显示 `—` |
| **入参/出参** | 基于 xform API 调用推断的角色，详见下方 |

### 入参/出参角色

| 角色 | 判定 API | 语义 |
|---|---|---|
| **读取** | `GetXFormFieldById` / `GetXFormFieldValueById` | JS 从该控件取值 |
| **写入** | `SetXFormFieldValueById` | JS 修改该控件的值 |
| **监听** | `AttachXFormValueChangeEventById` | JS 监听该控件的值变化事件 |

- 同一控件可能兼具多种角色，按 `读取 → 写入 → 监听` 顺序显示，用 ` · ` 拼接（例如 `读取 · 监听`）
- 无任何角色时显示 `—`

### ⚠️ 已知限制：间接写入不会被识别

典型场景：

```javascript
var elem = GetXFormFieldById("fd_xxx", true);  // 拿到 DOM 元素数组
elem[0].value = "new value";                    // 间接写入
```

上述代码中 `fd_xxx` 仅会被标记为 `读取`，因为工具基于 API 调用点做静态分类，不做数据流分析。阅读者需要结合「JS 片段（合并）」源码自行判断。

**识别技巧**：如果某控件标记为 `读取`，且 JS 中出现 `GetXFormFieldById(id, true)`（第二个参数为 `true`，表示返回 DOM 元素数组），则大概率后续会有间接写入操作，需手动核查。

### 直接引用 vs 行级引用

- **直接引用**：`GetXFormFieldById("fd_ChanPinType")` 中的 `fd_ChanPinType` 算 1 次直接引用
- **行级引用**：子表字段在 JS 中常以 `<子表ID>.<行号>.<字段ID>` 格式访问特定行的值，例如 `GetXFormFieldValueById("fd_3aa1c3c0849216.0.fd_ChanPinType")` 算 1 次行级引用
- 同一控件可能同时有直接引用和行级引用，两列分别计数
- 直接引用计数已扣除行级引用消费的部分，避免重复

## 其他章节说明

### 表单元信息

- **主表**：`standardTable` 类型的容器，通常一个表单只有一个
- **子表**：`detailsTable` 类型的容器（明细表），可多个；子表字段在 JS 中常以行级引用形式访问
- **业务控件总数**：排除布局/展示类控件（`textLabel`、`brcontrol`）后的控件数量
- **JSP 片段数量**：表单中嵌入的 JSP 代码片段数量（每个片段含一段 JS）

### 未匹配引用

当 JS 中调用了已知 API（xform ID API、`document.getElementById`、`$("#xxx")`），但参数不在控件字典中时，记录到此表。

| 列名 | 含义 |
|---|---|
| **原始参数** | API 调用中的字符串参数 |
| **出现的 API** | 命中该参数的 API 名列表（去重） |
| **未匹配原因** | `未知 ID` / `未知子表` / `子表字段未知` |

常见原因：
- 表单 HTML 不完整（缺少某些控件）
- JS 引用了已删除的控件
- 控件 ID 拼写错误

### 全局钩子

检测两种全局事件机制：

- **声明 `XFormOnValueChange` 函数**：表单级值变化钩子，任何控件值变化都会触发
- **`XFormOnValueChangeFuns.push(...)` 次数**：向全局钩子数组注册回调的次数

迁移到 React 时，这些钩子通常需要转换为统一的 `onChange` 处理器或状态管理逻辑。

### 按 label 引用

罕见情况：JS 通过 ByLabel API（如 `GetXFormFieldByLabel("姓名")`）引用控件。

- 工具会尝试匹配 `control.label === 提取值` 的控件
- 匹配到的控件 ID 列在 `matchedControlIds`
- 悬空 label（无匹配控件）也会保留记录

迁移时需注意：label 可能随多语言或 UI 调整变化，基于 label 的引用不如基于 ID 稳定。

### 解析警告

记录解析过程中的异常，例如：

- JSP 片段找不到 `input[type=hidden]`
- 其他结构异常

无异常时整节省略。

## 输出二：字段映射模板

工具同时生成一份「字段映射模板」，仅包含 JS 实际引用的字段（不是全部控件）。

### 模板格式

```
字段映射（共 N 个）

1. 旧ID: fd_ChanPinType
   label: 产品类型 | 类型: select | 所属: 子表: 产品拆解明细表 | 角色: 读取 · 监听
   新ID: 

2. 旧ID: fd_CustomType
   label: 产品类型自定义 | 类型: inputText | 所属: 子表: 产品拆解明细表 | 角色: 读取
   新ID: 
```

### 各字段含义

| 字段 | 说明 |
|---|---|
| **旧ID** | 旧系统（EKP JSP 表单）中的控件 ID |
| **label** | 控件的显示标签，用于在新系统中定位对应字段 |
| **类型** | 控件的 `fd_type`，新旧系统字段类型基本一致 |
| **所属** | 控件所在的表（主表 / 子表） |
| **角色** | JS 对该控件的操作类型（读取 / 写入 / 监听） |
| **新ID** | 留空，由用户填写新系统中对应字段的 ID |

### 使用流程

1. 复制模板到新系统的 JS 编辑器面板
2. 对照每个字段的 label，在新表单中找到对应字段
3. 点击该字段获取新 ID，填入「新ID:」后面
4. 完成后将填好的映射表交给迁移 Agent

## 如何使用本报告进行迁移

1. **先看「表单元信息」**：了解表单的主表/子表结构和规模
2. **重点看「JS 引用的控件」表格**：
   - `读取` 角色的控件 → React 中需要作为数据源（state/props）
   - `写入` 角色的控件 → React 中需要作为数据目标（setState）
   - `监听` 角色的控件 → React 中需要绑定 `onChange` 处理器
3. **结合「JS 片段（合并）」源码**：理解具体业务逻辑
4. **检查「未匹配引用」**：确认是否有遗漏的控件或拼写错误
5. **注意「全局钩子」**：设计统一的值变化处理机制
6. **⚠️ 警惕间接写入**：对于标记为 `读取` 但 JS 中有 `GetXFormFieldById(id, true)` 的控件，手动检查后续是否有 `.value = ...` 赋值
7. **使用字段映射模板**：复制到新系统 JS 编辑器，对照 label 点击字段获取新 ID，填好后交给迁移 Agent
