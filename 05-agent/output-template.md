# 输出 JS 骨架模板

> Agent 生成的 `mk-form.js` **必须**遵循本模板结构。
> 目的：保证多份迁移产出风格一致、可读性强、便于人工审阅与后续维护。

---

## 完整模板

```javascript
/**
 * ============================================================
 * 表单名称: <form-name>（如: 产品拆解申请表）
 * 源系统:   蓝凌 EKP 低代码表单
 * 目标系统: 蓝凌 MK-PaaS
 * 迁移时间: <YYYY-MM-DD HH:mm>
 * Agent 版本: v0.1
 * 源分析报告: 06-workspace/inputs/<form-name>/analysis-report.md
 * 字段映射表: 06-workspace/inputs/<form-name>/field-mapping.txt
 * ============================================================
 *
 * 【迁移概览】
 * - 引用控件总数: <N>
 * - JSP 片段数: <M>
 * - 输出代码段数: <K>
 * - 配置化建议项: <P>（详见 migration-notes.md）
 * - 未处理项: <Q>（详见 migration-notes.md）
 *
 * 【字段映射速查】（完整表见 field-mapping.txt）
 * <oldId1> (<label1>) → <newId1>
 * <oldId2> (<label2>) → <newId2>
 * ...
 *
 * 【注意事项】
 * 1. 本文件为 MK 表单 JS 面板脚本，粘贴到 MK 表单设计器 → JS 面板
 * 2. 执行时机: 表单加载后自动执行（无需 $(document).ready）
 * 3. 依赖: window.MKXFORM 全局对象
 * 4. 禁止: DOM 操作、jQuery、alert/confirm
 */

// ============================================================
// 段 1: <业务逻辑简要描述，如"产品类型变化时联动自定义输入框">
// ------------------------------------------------------------
// 对应 EKP 原逻辑:
//   <简要说明原 JSP 片段中做了什么，2~3 行>
// 应用规则:
//   - api-mapping-table.md §1.2 (onChange 事件监听)
//   - detail-table-patterns.md 模式 3 (按条件差异化处理每行)
//   - indirect-write-patterns.md 模式 B/C (必填切换)
// ============================================================

function handleChanPinTypeChange() {
  var rowCount = MKXFORM.getRowCount("fdNewTable");
  for (var i = 0; i < rowCount; i++) {
    var chanPinType = MKXFORM.getControlValue("fdNewTable.fdNewChanPinType", i);

    if (chanPinType == "0") {
      // 显示 + 必填
      MKXFORM.setDetailFieldItemAttr("fdNewTable", 5, i, "fdNewCustomType");
      MKXFORM.setDetailFieldItemAttr("fdNewTable", 3, i, "fdNewCustomType");
    } else {
      // 隐藏 + 非必填 + 清空值
      MKXFORM.setDetailFieldItemAttr("fdNewTable", 4, i, "fdNewCustomType");
      MKXFORM.setDetailFieldItemAttr("fdNewTable", 6, i, "fdNewCustomType");
      MKXFORM.updateControl("fdNewTable.fdNewCustomType", i, "");
    }
  }
}

// 注册监听
MKXFORM.onChange("fdNewTable.fdNewChanPinType", function(value, extValue) {
  handleChanPinTypeChange();
});

// 初始化时执行一次
handleChanPinTypeChange();


// ============================================================
// 段 2: <下一段业务逻辑>
// ------------------------------------------------------------
// 对应 EKP 原逻辑:
//   <...>
// 应用规则:
//   - <...>
// ============================================================

// <代码>


// ============================================================
// 段 N: 提交前校验（若原 EKP 有）
// ------------------------------------------------------------
// 对应 EKP 原逻辑:
//   <原 jQuery submit 拦截 / 自定义校验函数>
// 应用规则:
//   - api-mapping-table.md §3.2 (消息提示)
//   - MKXFORM.beforeSubmit
// ============================================================

MKXFORM.beforeSubmit(function() {
  // 校验逻辑
  var amount = MKXFORM.getValue("fdNewAmount");
  if (amount === null || amount <= 0) {
    return false;   // 阻止提交
  }
  return true;      // 允许提交
}, "金额必须大于 0");


// ============================================================
// 段 N+1: 提交后回调（若原 EKP 有）
// ------------------------------------------------------------
// 对应 EKP 原逻辑:
//   <...>
// 应用规则:
//   - MKXFORM.afterSubmit
// ============================================================

MKXFORM.afterSubmit(function() {
  MKXFORM.message.success("提交成功");
});


// ============================================================
// 配置化建议（不生成 JS，仅注释提示）
// ------------------------------------------------------------
// 以下逻辑建议通过 MK 表单设计器配置实现，详见 migration-notes.md:
//
// 1. 字段默认值:
//    - fdNewUnit (单位) → 默认值 = "台"
//
// 2. 显示条件:
//    - fdNewCustomType → 当 fdNewChanPinType == "0" 时显示
//
// 3. 必填条件:
//    - fdNewCustomType → 当 fdNewChanPinType == "0" 时必填
// ============================================================


// ============================================================
// 未处理项 / 需人工确认（不生成 JS，仅注释提示）
// ------------------------------------------------------------
// 1. <描述> — 原因: <...>
// 2. <描述> — 原因: <...>
// ============================================================
```

## 模板要素说明

### 1. 头部注释块（必填）

包含 8 项元信息：
- 表单名称
- 源系统 / 目标系统
- 迁移时间
- Agent 版本
- 源分析报告路径
- 字段映射表路径
- 迁移概览（数字统计）
- 字段映射速查（前 5~10 条）

**作用**：便于后续维护者快速了解上下文。

---

### 2. 代码段分隔注释（必填）

每段代码前必须有 **3 部分注释**：

```
// ============================================================
// 段 N: <业务逻辑简要描述>
// ------------------------------------------------------------
// 对应 EKP 原逻辑:
//   <2~3 行说明>
// 应用规则:
//   - <规则文档 §章节>
//   - <规则文档 §章节>
// ============================================================
```

**作用**：
- 让审阅者无需对照 EKP 源码即可理解每段意图
- 让后续维护者知道每处转换的依据
- 便于回溯 bug（若某段逻辑有误，可快速定位到规则文档）

---

### 3. 函数封装（推荐）

复杂逻辑封装为具名函数，而非匿名回调内联：

```javascript
// ✅ 推荐
function handleChanPinTypeChange() {
  // 逻辑
}
MKXFORM.onChange("fdNewChanPinType", handleChanPinTypeChange);
handleChanPinTypeChange();   // 初始化调用

// ❌ 不推荐（难以复用与调试）
MKXFORM.onChange("fdNewChanPinType", function() {
  // 大段逻辑内联
});
```

**作用**：
- 便于初始化时调用一次
- 便于多处复用
- 便于单元测试

---

### 4. 配置化建议注释块（必填）

即使某些逻辑已通过 MK 配置实现（不在 JS 中），也要在文件尾部以注释形式列出：

```javascript
// ============================================================
// 配置化建议（不生成 JS，仅注释提示）
// ------------------------------------------------------------
// 1. 字段默认值: fdNewUnit → "台"
// 2. 显示条件: fdNewCustomType → 当 fdNewChanPinType == "0"
// ============================================================
```

**作用**：
- 提醒部署人员在 MK 设计器中完成配置
- 避免遗漏

---

### 5. 未处理项注释块（必填，若无则写"无"）

```javascript
// ============================================================
// 未处理项 / 需人工确认
// ------------------------------------------------------------
// 1. 人员字段 fdNewApplicant 原 EKP 只存姓名，MK 需要完整对象
//    — 需人工确认数据来源（是否通过 callOrg 查询）
// 2. 分析报告【未匹配引用】中的 "fd_deletedField"
//    — 原表单可能已删除该字段，需人工确认是否忽略
// ============================================================
```

**作用**：显式暴露风险，避免静默失败。

---

### 6. 字段 ID 注释规范（必填）

MK 的新 ID 是随机码（如 `mk_model_20260814ixaba.fd_3db44b529c8760`），单看 ID 无法识别业务含义。因此：

1. **每个字段 ID 出现处必须有行内注释**，格式：`中文 label + 表归属`（注释紧邻 ID 所在代码行，不要重复写 ID）
2. **关键逻辑语句/分支必须有中文注释**说明"做了什么"（如锁定、赋值、显隐动作）

```javascript
// 决策评审点（主表 - 下拉框）
var jdspId = "mk_model_20260814ixaba.fd_3db44b529c8760";
// 角色（决议表子表 - 下拉框）
var roleId = "mk_model_20260814ixaba_d_0a02c.fd_role";

if (MKXFORM.getValue(jdspId) === "ADCP") {
  // 强制首行"角色"填为"知识产权委员"
  MKXFORM.updateControl(roleId, 0, "知识产权委员");
  // 锁定"角色"字段（1 = 设为只读）
  MKXFORM.setDetailFieldAttr(roleId, 1);
}
```

**作用**：人工核对、联调、后续维护时无需回查字段映射表即可确认 ID 与业务字段的对应关系。

## 代码风格约定

| 项 | 约定 |
|---|---|
| 缩进 | 2 空格 |
| 分号 | 语句末尾加分号 |
| 引号 | 字符串用双引号 `"` |
| 变量声明 | 用 `var`（兼容性最好），或 `let`/`const`（若 MK 环境支持） |
| 函数命名 | 驼峰式，动词开头（`handleXxx`、`updateYyy`、`validateZzz`） |
| 注释语言 | 中文 |
| 字段 ID 注释 | 每个 ID 出现处必须行内注释：中文 label + 表归属（不重复写 ID）（见「模板要素说明 §6」） |
| 代码标识符 | 英文 |
| 行宽 | ≤ 100 字符 |
| 空行 | 段之间空 2 行，段内逻辑块之间空 1 行 |

## 完整最小示例

```javascript
/**
 * ============================================================
 * 表单名称: 示例表单
 * 源系统:   蓝凌 EKP
 * 目标系统: 蓝凌 MK-PaaS
 * 迁移时间: 2026-09-17 10:00
 * Agent 版本: v0.1
 * ============================================================
 */

// ============================================================
// 段 1: 申请类型变化时联动说明字段
// ------------------------------------------------------------
// 对应 EKP 原逻辑:
//   监听 fd_ApplyType 变化，当值为"其他"时显示 fd_Remark，否则隐藏
// 应用规则:
//   - api-mapping-table.md §1.2 (onChange)
//   - api-mapping-table.md §1.3 (setFieldAttr 显隐)
// ============================================================

function handleApplyTypeChange(value) {
  if (value === "其他") {
    // 备注（主表 - 多行文本）
    MKXFORM.setFieldAttr("fdNewRemark", 5);   // 显示
  } else {
    // 备注（主表 - 多行文本）
    MKXFORM.setFieldAttr("fdNewRemark", 4);   // 隐藏
  }
}

// 申请类型（主表 - 下拉框）
MKXFORM.onChange("fdNewApplyType", handleApplyTypeChange);
handleApplyTypeChange(MKXFORM.getValue("fdNewApplyType"));   // 初始化


// ============================================================
// 配置化建议
// ------------------------------------------------------------
// 无（本例逻辑简单，也可通过 MK 字段"显示条件"配置实现）
// ============================================================


// ============================================================
// 未处理项
// ------------------------------------------------------------
// 无
// ============================================================
```
